Magpie 的多账号号池插件：把一批 ChatGPT 普号批量导入本机，后台自动登录、自动同步成 Magpie
Providers，按剩余额度轮换、失败自动换号。**凭证只在本机处理，不上传任何地方。**

这一版只改一件事：**卡死的号隔离得更久，而且按连续次数升级。**

## 装 / 升级

Magpie → 「插件」→「发现」→ 底部输入框填：

```
https://github.com/puaicg/magpie-gptpool
```

已经装过旧版的，推一下更新即可（`bun update magpie-gptpool` + 重启）。**账号库不动**
（`~/.magpie-gptfree/`），provider id 仍是 `gptfree-pool`，已保存的模型名继续可用。

## 改了什么

以前：一次卡死（`worker_timeout`）按**两次失败**计，并且固定冷却 **5 分钟**。

5 分钟太短。一个真的卡死的号一小时能回来捣乱十几次，每次都要白烧掉整条 lane 的
预算（单次 40 秒）—— 客户端那边看到的就是「越来越慢」。

现在：

| 连续卡死次数 | 隔离时长 |
| --- | --- |
| 1 次 | 不隔离（可能只是上游抖一下） |
| 2 次 | 30 分钟 |
| 3 次及以上 | 2 小时 |

**只在成功时清零。** 普通失败既不加也不清 —— 卡死是独立信号，不该被别的错误冲掉。

同时把「按两次失败计」这个老做法去掉了：双倍计数原本是为了让一次卡死就能触发普通
冷却阶梯，现在卡死有自己的阶梯，再乘 2 等于同一件事罚两遍，还会把普通阶梯的阈值搅乱。

## 顺带修的一个 bug

冷却时间原来是无条件覆盖的。卡死三次被隔离 2 小时之后，只要来一次普通失败，就会把它
**覆盖成 10 分钟** —— 隔离等于白做。现在改成只延长、不缩短。

## 会有什么变化

- 单次卡死不再立刻冷却。偶尔抖一下的号会多挨一次尝试 —— 这是刻意的，换来的是
  真正卡死的号被隔离得久得多。
- 普通失败仍然要连续 3 次才进冷却，这条没变。
- 分级里「连续卡死 ≥2 次 → C 级」的判据不变，读的还是同一个计数。

## 测试

253 个用例。新增的三条分别钉住：阶梯本身（0 → 30min → 2h，成功清零）、
「普通失败不能缩短已有隔离」、以及「单次普通失败仍然不冷却」。
