Magpie 的多账号号池插件：把一批 ChatGPT 普号批量导入本机，后台自动登录、自动同步成 Magpie
Providers，按剩余额度轮询、失败自动换号。**凭证只在本机处理，不上传任何地方。**

这一版**只加日志**：生图失败时把上游原话留下来，翻得出历史，也能在面板上直接看。

## 装 / 升级

Magpie → 「插件」→「发现」→ 底部输入框填：

```
https://github.com/puaicg/magpie-gptpool
```

已经装过旧版的，推一下更新即可（`bun update magpie-gptpool` + 重启）。**账号库不动**
（`~/.magpie-gptfree/`），provider id 仍是 `gptfree-pool`，已保存的模型名继续可用。

## 这一版改了什么

0.8.14 把「上游只回文字」的原文存进了账号账本，但账本每个号**只留最后一次**失败 ——
同一个号失败第二次，第一次的原因就没了。真出问题时往往是一批号连着挂，事后想复盘
「昨天那波到底是限流还是封号」，账本已经翻不出来。

所以加一份只追加的日志：`~/.magpie-gptfree/image-errors.jsonl`（0600，一行一条，
只留最近 500 条）。每次账号失败写一条：

```json
{"at":"2026-11-16T02:14:07.512Z","code":"upstream_text_reply","tag":"sc94d678a8c","status":502,"message":"图片生成功能暂时不可用。输出尺寸要求：1024 × 1024。"}
```

- `tag` 是 `s<sha256 前 10 位>`，**不落邮箱明文**；
- `message` 走和账本同一套脱敏（token / 邮箱 / URL 全部替换），压平换行，截断 240 字；
- 只在失败时写，成功不写；
- 只在账本真正落盘时写 —— 内存账本（测试）不会往 `~/.magpie-gptfree` 里丢文件。

**面板上能看了**：设置页「清理日志」下面多一块「生图错误日志」，五列 ——
时间 / 账号 / 错误码 / 状态 / 上游原文。错误码有中文标签，鼠标停上去还有一句人话；
账号显示遮罩邮箱（悬停看槽位号）；原文太长会截断，悬停看全文。带「刷新」和「清空日志」。

也可以直接看文件：

```bash
docker exec <容器名> tail -n 50 /config/home/.magpie-gptfree/image-errors.jsonl
```

（`MAGPIE_GPTFREE_HOME` 改过的话按实际路径来。）

## 顺便修了三处「日志不准」

这一版一边加日志，一边把实测发现的三处失真改掉了：

1. **`status` 曾经是编的**。上游把生图请求当文字答回来时，它返回的其实是 **HTTP 200**
   （流正常走完，只是内容不是图），而我们一直记 `502`——看日志的人会以为上游网关挂了。
   现在上游真实码单独记一列（`upstreamStatus`），和我们返回给客户端的码并排放；
   面板「上次失败」悬停也会写「上游实际返回：200（流是好的，只是内容不是图）」。
2. **「上游临时不可用」不再算进限流**。`temporarily unavailable` / `暂时不可用` 原来被
   `upstream_rate_limited` 抢走。可「上游自己不行」和「你这个号请求太频繁」是两件事：
   一个该等，一个该换号。新增 `upstream_unavailable` 分类。
3. **整单失败多记一条汇总**。池子 20 个号、55 秒预算只够试 7 个时，原来只有 7 条失败，
   剩下 13 个「没轮到」和「试了失败」长得一模一样，很容易误读成「全部号都挂了」。
   现在多一条 `kind: "request"` 记录：试了几个 / 池子一共几个 / 几个没轮到 / 总耗时，
   和账号记录共用一个 `requestId`。面板上就是「整单 · 试 7/23」+「16 个号没轮到」。

## 想自己核对一次失败

插件日志（面板上那份）是**按账号**记的；Magpie 网关另有一份**按请求**的日志，两者互补：

```bash
docker logs magpie 2>&1 | grep 'gateway:' | tail -20
# gateway: curl's call to gptfree-pool/gpt-image-2 on gptfree-pool failed:
#   504 after 55.084s: gptfree-pool: 504 Gateway Timeout: 生图超时…
```

它只打**失败**的请求，一次请求一行，带客户端看到的最终状态码和总耗时——但看不到
中间试了哪些号（那在插件的错误日志里）。对照着看：网关说「55 秒超时」，
插件说「试了 7 个号、16 个没轮到、每个都撞上上游回文字」，一次失败就完整了。
